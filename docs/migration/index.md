# Migrate scene-maker JSON policy to version 1 TOML

The scene-maker bootstrap JSON and `raften` version 1 TOML express different contracts. Treat migration as a reviewed first adoption, not a syntax conversion. Work in an isolated clean clone, keep the old checker available until results are classified, and do not modify the original working directory during evaluation.

## Field mapping

| Scene-maker JSON | Version 1 TOML | Migration rule |
| --- | --- | --- |
| `policy_version` | top-level `version` | Set `version = 1`; do not copy the old numeric value blindly. |
| `max_text_bytes` | final scanned authored `[[file_rule]].hard_bytes` | Preserve the old ordinary hard ceiling unless the owner deliberately tightens it. Add an owner-selected `warn_bytes` below it because the old schema has no warning ceiling. |
| `index_max_bytes` | `[[path_override]]` for each root's `**/index.md` paths | Preserve the stricter effective ceiling; old behavior selected the minimum applicable limit. |
| `entrypoint_limits[path]` | exact `[[path_override]]` with `path` | Preserve the stricter effective ceiling for each named path. |
| `documentation_roots = ["docs"]` | `[documentation].roots = ["docs/index.md"]` | Name actual root documents, then review the newly ancestor-aware graph. |
| `documentation_excluded_globs` | `[documentation].exclude` | Translate only exclusions with a current, documented reason. Version 1 globs have explicit repository semantics. |
| `required_entrypoint_links` | one `[[entrypoint]]` per source | Convert each source and its required targets explicitly. |
| `text_excluded_globs` | ordered named `[[file_rule]]` entries | Classify generated, vendored, fixture, lock, or legal material narrowly before the authored catch-all. Every rule needs an auditable reason. |
| `legacy_oversize` | migration-debt sidecar generated by `init --capture-debt` | Never convert fixed ceilings to overrides or exceptions. Version 1 records exact current bytes and SHA-256, then ratchets against the immediate base blob. |

Add the required `[repository]`, `[output]`, `[ratchet]`, and `[exceptions]` tables and project-specific context sets. Start from `raften init` output rather than attempting to invent missing version 1 defaults by hand.

## Safe adoption sequence

1. Create a local clone at the exact commit to be evaluated and confirm it is clean.
2. Run the reviewed `raften` artifact with `init --capture-debt --repo <clone>`. This writes the deterministic starter policy and a versioned exact debt sidecar; the sidecar has an empty `entries` array when no oversized authored path needs migration debt.
3. Replace starter classifications, document roots, entrypoints, and context sets with narrow project-reviewed values. Keep the authored catch-all last.
4. Do not carry broad `config/*.json` or `schemas/*.json` exclusions forward. Authored configuration and schemas remain scanned; classify only demonstrated generated or fixture paths.
5. Run `check`, `audit --format json`, and representative `explain --format json` commands with `--base-ref HEAD` and a fixed `--evaluation-date`. HEAD intentionally has no version 1 policy during first adoption, so the sidecar is the only valid migration-debt authority.
6. Review every unscanned rule, warning, exception, new graph diagnostic, and debt entry. Correct false classifications in policy; do not add shared-engine special cases.
7. Commit the TOML policy and debt sidecar together, then run against the immediate parent on each later change. Partial size reductions become the next automatic ceiling and debt disappears when a file returns below its ordinary limit.

Expected differences from the seed include strict TOML validation, explicit glob semantics, ancestor directory indexes, reachability and fragment checks, no automatic structured-data bypass, stable structured diagnostics, and immediate-base ratchets. The detailed compatibility inventory is in [the scene-maker compatibility reference](../reference/scene-maker-compatibility.md).
