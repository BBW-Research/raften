## Phase 3 completion evidence

- Completed: 2026-09-01.
- Policy resolution: `size_policy.py` compiles every rule, override, exception, and context pattern once. Resolution records first-rule and first-pattern provenance, exact-over-pattern and most-specific-pattern override precedence, monotonic ordinary limits, exact-over-pattern intentional exceptions, injected-date expiry, and distinct ordinary versus effective scan and threshold state.
- Evaluation: `sizes.py` classifies NUL and strict UTF-8 states, measures exact raw bytes, emits only the strongest advisory or blocking threshold diagnostic, retains requested plaintext for later parsing without another read, reports unclassified and ineffective policies, computes declaration-ordered context sets with path-sorted de-duplicated membership, distinguishes every missing exact-member state, and exposes immutable audit and explain records.
- Repository reads: regular inventory entries carry mode, device, inode, size, modification time, and change time. The public current-content reader uses descriptor-relative no-follow and nonblocking opens, bounds reads to snapshot size plus one byte, verifies descriptor and path identity before and after reading, distinguishes observed path changes as `GIT005`, and fails closed as `GIT009` when secure primitives are unavailable.
- Audit: largest governed files sort by descending raw size then path and retain effective policy, including explicit authored, generated, vendored, fixture, legal, and intentional-exception state. Classification counts and explain resolution are deterministic for both inventoried and nonexistent canonical paths.
- Diagnostics: run-time configuration identities `CFG014` and `CFG015`, budget identities `CTX001` through `CTX005`, and injected-date expiry identity `EXC002` have stable severities, locations or field paths, and structured details. Equal-specificity overlapping exception patterns now receive the existing static ambiguity identity `CFG011`.
- Contract: `docs/specs/file-budgets-v1.md` is authoritative for classification, exceptions, content reads, thresholds, context accounting, audit, explain, and diagnostic semantics. Architecture and configuration documents link to it. Completed phase evidence moved into this companion log so the executable plan remains below its policy ceiling without losing history.

Direct evaluation of the repository's 96 Git-visible files reports one advisory `CTX001` for an existing test file, no blocking diagnostic, and a within-limit bootstrap context.
