# Standalone tool phase 5 evidence

This companion to the [completed standalone-tool plan](standalone-tool.md) retains phase evidence so the executable checklist remains compact. Evidence moved here only after its phase gate was complete.

## Phase 5 completion evidence

- Completed: 2026-09-02.
- Contract and model: `docs/specs/ratchets-v1.md` is authoritative for current-candidate eligibility, Git and first-adoption baselines, diagnostic reconciliation, unavailable states, manifest bytes, the conservative policy partial order, and stable `RAT001` through `RAT013` identities. Immutable records distinguish baseline source, migration state, observed base size and identity, and a real migration ceiling; ineligible baselines never advertise a ceiling.
- File ratchet: pure evaluation considers only present regular authored plaintext above the current ordinary hard limit, ignores intentional-exception relief, and compares exact paths against the immediate base blob. New paths, ordinary-sized bases, ineligible types or content, and growth fail; equal size and partial reduction remain debt; returning within the ordinary limit clears debt without a base read. Only proven debt suppresses the ordinary `CTX002`, preserving the raw assessment for audit and explain.
- Git behavior: recursive base-tree metadata now includes directories so directory-to-file replacement is a deterministic type change. Regular and executable blobs share one eligible type; symlinks, gitlinks, trees, non-blobs, NUL data, and invalid UTF-8 do not. Rename behavior is exact delete-plus-add, and real repository tests verify comparison leaves HEAD, index bytes, staged state, and worktree bytes unchanged.
- First adoption: a strict versioned JSON sidecar captures only exact oversized-candidate paths, positive raw sizes, and SHA-256 content identities. Parsing rejects duplicate or unknown keys, unsafe paths, selector-shaped fields, invalid numbers and identities, and duplicate entries. Literal Git filename metacharacters and JSON-escaped characters retain exact path identity. Once a base policy exists, Git takes precedence over the sidecar.
- Policy ratchet: split comparison modules enforce the base-controlled partial order for file-rule identity and ordering, finite limits, overrides, unscanned coverage, documentation roots and graph flags, entrypoints, context sets, ratchet switches, and governed exceptions. Conservative overlap checks prevent selector rewrites, rule reordering, nested reachability seeds, or fallback exposure from silently weakening policy. Size evaluation and policy comparison share one authoritative fail-closed `CFG015` predicate.
- Determinism: absent and all-zero base refs are distinct nonblocking unavailable states; nonzero resolution, shallow-history, tree, blob, and type failures retain operational Git identities. Base-policy absence and first-adoption precedence are specified for Phase 6 orchestration. All collections and diagnostics are explicitly sorted, and pure comparators perform no filesystem, subprocess, environment, or clock access.
- Tests: 62 tests added since Phase 4 cover the full file truth table, partial-reduction ceilings, diagnostic reconciliation, manifest round trips and malformed input, every policy domain, fail-closed exception transitions, exact filename semantics, rename and type changes, real Git blob comparison, and non-mutation. The full suite contains 367 tests with one host-filesystem capability skip.
- Validation: `scripts/validate`, warnings-as-errors suites on Python 3.12 and 3.13, the transitional policy check with `--base-ref HEAD`, `git diff --check`, offline Lychee validation, and the frozen-oracle hash check pass. The frozen checker remains byte-identical at `bb796f2304f3692089a5e87cef55a7fbe3e7c4c9521d6d2299b738a84f7ebd11`.
- Review: the read-only reviewer verified fixes for rule-order and guard interactions, unscanned coverage, nested documentation roots, exception fallback exposure, fail-closed `CFG015` transitions, exact manifest filename semantics, tree metadata, and invalid migration ceilings. The shared effective-policy predicate removes drift between current-state and policy-ratchet enforcement. No review finding remains open.
- Remaining work: Phase 6 owns runner selection among Git, manifest, absent-ref, and operational-error outcomes; public output; `audit` and `explain`; and guarded `init --capture-debt` writes. Phase 7 owns normal-workflow self-hosting and retirement of the frozen transitional checker.
- Risks: policy-pattern removal and overlap remain deliberately conservative where general glob containment is not proven, so an intentional tightening may still require owner review. Local execution evidence is macOS arm64; Linux remains a Phase 8 release-matrix requirement, while Windows is outside the supported-platform scope under [decision 0005](../../decisions/0005-supported-platforms.md).
