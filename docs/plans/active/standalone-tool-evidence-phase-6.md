# Standalone tool Phase 6 evidence

- Completed: 2026-09-02.
- Command orchestration: `runner.py` selects the current TOML policy, Git base policy, first-adoption debt manifest, or deterministic unavailable-baseline state without consulting the network or wall clock. One inventory snapshot and per-path content cache feed size, Markdown, ratchet, audit, and explain evaluation, while current config and sidecar reads use the same descriptor-relative no-follow boundary.
- CLI: `check`, `audit`, `explain`, and `init` run end to end against explicit absolute or relative repository roots, including when the process starts outside the repository. Semantic exits are `0` for a complete successful command, `1` for a complete blocking check, and `2` for invalid input or an incomplete operation. Help, version, reports, and failures handle broken pipes without tracebacks, and machine output is UTF-8 regardless of the ambient text locale. Package metadata reads the single authoritative `repo_context.__version__` constant.
- Output contract: `docs/specs/output-v1.md` defines stream routing, exit status, deterministic text, versioned JSON, SARIF, audit, explain, init, and `CLI001` through `CLI004`, `RUN001`, and `INIT001` through `INIT004`. Text emits one final summary; JSON schema projections retain structured diagnostics and provenance; SARIF includes only real positive source regions; emergency rendering has a deterministic shape.
- Audit and explain: audit reports every governed current path, including unavailable-size states, explicit authored/generated/vendored/fixture/legal classifications, effective thresholds, context metrics, exception status, and ordered base changes. Explain accepts literal Git filename metacharacters and POSIX control or backslash bytes at the candidate boundary, reports complete rule and override provenance, and filters path-, exception-, and context-scoped diagnostics that do not apply to the selected path.
- Initialization: starter policy generation is deterministic and refuses dirty repositories or uncaptured first-adoption debt. Non-capture runs protect sidecar absence through config activation; capture writes the sidecar before config even when its entry list is empty. Descriptor-anchored root and parent checks, exclusive temporary and quarantine creation, no-overwrite publication, forced-target quarantine and identity verification, directory synchronization, final group-boundary identity and absence checks, and identity-safe rollback preserve concurrent or displaced data under path-scoped diagnostics and reported repository-relative recovery names.
- Tests: 91 tests added since Phase 5 cover orchestration, all renderers, command integration, audit and explain projections, initialization policy/debt behavior, output encoding and broken pipes, exact Git filename handling, and adversarial destination, parent, auxiliary-file, rollback, and group-commit races. The complete suite contains 458 tests with one host-filesystem capability skip.
- Validation: `scripts/validate`, `BASE_REF=HEAD scripts/validate`, warnings-as-errors suites on Python 3.12.14 and 3.13.13, target text/JSON/SARIF/audit/explain/HEAD smokes, `git diff --check`, and offline Lychee validation pass. The frozen checker remains byte-identical at `bb796f2304f3692089a5e87cef55a7fbe3e7c4c9521d6d2299b738a84f7ebd11`, and every authored file remains below its policy ceiling.
- Review: the read-only Phase 6 reviewer verified fixes for base/config precedence, stale ratchet diagnostics, complete audit projection, explain diagnostic scoping, SARIF locations, locale-independent and emergency output, literal candidate paths, root and parent descriptor lifetimes, no-overwrite activation, forced-target ownership, auxiliary identity checks, rollback and recovery reporting, final artifact identity sweeps, and the late absence-guard race. The final review reports no findings and confirms the behavioral gate is satisfied.
- Remaining work: Phase 7 switches normal validation and CI from the frozen bootstrap oracle to the new engine, classifies seed-versus-target output differences, and makes the repository self-host under the TOML policy. The bootstrap JSON and frozen checker therefore remain intentionally transitional in this phase.
- Risks: local cross-version evidence is macOS arm64. Linux installation and distribution qualification remain Phase 8 work. One non-UTF-8-filename test skips when the host filesystem cannot create that byte sequence. Windows is intentionally outside the supported scope under [decision 0005](../../decisions/0005-supported-platforms.md).
